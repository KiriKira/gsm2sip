# 短信备份、导出与导入

两端 Android 应用的“短信备份与归档”入口使用同一文件格式。备份由用户选择文件位置，不依赖中转服务器在线；导出范围是当前设备已经保存的短信和本机导入归档，尚未同步到该设备的服务器历史不会自动包含在内。服务器完整快照另见服务器仓库的备份说明。

## 使用

- **加密备份**：设置至少 8 个字符的密码，再选择保存位置。换设备后可以用同一密码导入，不依赖原设备的 Android Keystore。密码遗失无法恢复。
- **导出 JSON**：项目的可读通用格式，保存来源、正文、时间、方向、状态和原始 SIM 信息。
- **导出 XML**：兼容 SMS Backup & Restore 的短信 `smses/sms` 格式；支持导入其 SMS 文件。MMS 不在本功能范围内，混有 MMS 的文件会整体拒绝。
- **导入**：选择文件；加密文件输入密码。完整验证后显示记录数量和来源，确认后才合并归档。重复导入同一份文件不会重复增加相同记录。
- **查看归档**：分页查看导入历史，计数只包含导入的归档；导出还会包含本机缓存和网关保留历史。正文预览最多 1000 个字符，长短信可以打开完整正文；导出保存完整内容。来源、所有者和原始 SIM 信息用于历史展示，不会绑定到当前 SIM 或账户。

JSON/XML 是明文，包含短信正文和号码。加密文件使用随机盐与随机 nonce、PBKDF2-HMAC-SHA-256（310000 次）和 AES-256-GCM；文件头也受认证。导入会验证完整文件及认证标签。

## 导入与恢复边界

导入写入独立的 `sms-archive.db`，不创建发送任务，不上传到服务器，不写入系统短信提供器，也不恢复 ACK、同步游标、通话状态、凭据或配对。历史显示为“待发送”或“未知”也不会被发送。

一份文件的导入在单个 SQLite 事务中完成。密码错误、文件截断、格式错误、相同 ID 的正文冲突、取消或预览后文件被修改都会使本次合并回滚；原有归档保留。较新的观察时间可以更新状态和 SIM 展示信息，正文与身份冲突不会静默覆盖。

解除配对会清理当前账户的运行缓存；已导入归档和保存在外部文件中的备份仍保留。导出包含当前账户缓存及此设备的归档；归档可能有多个来源，文件中的来源字段会保留。导入文件不会令应用以历史账户身份执行操作。

## 容量与兼容性

每份文件最多 64 MiB、100000 条短信，单条正文最多 1 MiB UTF-8，每个来源/号码等元数据字段最多 2048 字节。大于限制会明确失败，请拆分历史再导入。XML 使用标准类型 1–6，并以 `gsm2sip_*` 扩展保留项目元数据；第三方工具再次导出时可能移除扩展字段，此时可以读取短信内容，但不能保证与原项目 JSON 文件使用相同记录 ID。

XML 1.0 无法表达部分控制字符；包含这类字符的正文请使用 JSON 或加密备份。XML 导出在应用私有缓存中暂存条目以生成准确的 `count`，完成或失败后删除临时文件，因此需要额外可用存储空间。

长时间操作在后台工作线程执行，界面重建会保留正在执行的工作；进程被系统终止后不会自动重发或继续一次未完成导入。失败或取消的导出文件可能不完整，应删除后重新导出。
